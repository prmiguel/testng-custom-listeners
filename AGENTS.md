# AGENTS.md - TestNG Custom Listeners Project

## Project Overview

This is a TestNG custom listeners demonstration project that generates various report formats (Markdown, HTML, etc.) from test execution results.

## Build & Test Commands

### Build Project
```bash
mvn clean compile
```

### Run All Tests
```bash
mvn test
```

### Run Single Test Class
```bash
mvn test -Dtest=SampleTest
```

### Run Single Test Method
```bash
mvn test -Dtest=SampleTest#testSuccess
```

### Run Tests by Group
```bash
mvn test -Dgroups=smoke
mvn test -Dgroups=basic,smoke
```

### Run Specific TestNG Suite File
```bash
mvn test -Dsurefire.suiteXmlFiles=src/test/resources/testng.xml
```

### Skip Tests
```bash
mvn clean package -DskipTests
```

### View Test Reports
```bash
# TestNG HTML report
open target/test-output/index.html

# Custom reports generated by listeners
open target/test-report.html        # HtmlTestReporterListener
open target/TestReport.md          # MarkdownListener
open target/TestSummaryReport.md   # ExecutionSummaryMarkdownListener
open target/TestReportWithChart.md  # MarkdownListenerWithChart
open target/simple-report.md        # SimpleMarkdownReporterListener
```

## Code Style Guidelines

### Java Version & Compiler
- Target Java 11
- Use `<maven.compiler.source>` and `<maven.compiler.target>` properties

### Naming Conventions
- Classes: PascalCase (e.g., `CustomTestListener`)
- Methods: camelCase (e.g., `onTestSuccess`, `getParameters`)
- Variables: camelCase (e.g., `testResults`, `passedCount`)
- Constants: UPPER_SNAKE_CASE (e.g., `MAX_RETRIES`)
- Packages: lowercase with dots (e.g., `org.testng.listeners`)

### Imports
- Explicit imports preferred for clarity
- Wildcard imports acceptable for TestNG (`org.testng.*`) when using multiple interfaces
- Group imports: java.*, org.*, then third-party

### Formatting
- 4-space indentation (standard Java convention)
- Braces on same line (K&R style)
- One blank line between methods
- Line length: reasonable (no strict limit, use common sense)

### TestNG Conventions
- Use `@Test` annotation with explicit groups
- Test groups: `smoke`, `basic`, `failure`, `dataProvider`, `wip`, `skipped`
- Use `@DataProvider` for parameterized tests
- Use `dependsOnMethods` for test dependencies when needed
- Use `SkipException` for conditional test skipping

### Listener Implementation Pattern
```java
public class MyListener implements ITestListener, IExecutionListener {
    
    @Override
    public void onTestSuccess(ITestResult result) {
        // Handle success
    }
    
    @Override
    public void onTestFailure(ITestResult result) {
        // Handle failure
    }
    
    @Override
    public void onTestSkipped(ITestResult result) {
        // Handle skip
    }
    
    // Optional: implement lifecycle methods
    @Override public void onTestStart(ITestResult result) {}
    @Override public void onStart(ITestContext context) {}
    @Override public void onFinish(ITestContext context) {}
    
    // Private helper methods at bottom
    private void helperMethod() { }
}
```

### Error Handling
- Use try-with-resources for file I/O operations
- Catch specific exceptions (IOException over generic Exception)
- For report generation, print stack trace to stderr
- Validate null parameters in public methods

### Type Usage
- Use interfaces where possible (List, Map, Set)
- Use StringBuilder for string concatenation in loops
- Use AtomicInteger for thread-safe counters
- Prefer primitive types in DataProviders when possible

### File I/O
- Output reports to `target/` directory
- Use PrintWriter with try-with-resources
- Close resources explicitly or use try-with-resources

### Test Classes
- Place in `com.example.tests` package
- Use descriptive test method names
- Include assertion messages for clarity
- Log test execution with System.out

### Registering Listeners
Add to `src/test/resources/testng.xml`:
```xml
<listeners>
    <listener class-name="org.testng.listeners.YourListener"></listener>
</listeners>
```

## Key Dependencies

- TestNG 7.8.0

## Notes

- Reports are written to `target/` directory - ensure it exists
- Some listeners use emoji characters (passed/failed indicators)
- HTML reports use Chart.js via CDN for visualizations
- Markdown reports use Mermaid diagrams for charts
